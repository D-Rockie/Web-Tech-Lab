Part A — The fs (File System) module

Introduction

JavaScript in the browser is not allowed to touch files on your computer. Node.js runs on the server side, so it can, and fs is the built-in module used for that. No npm install is needed, we just import it. 

const fs = require('fs');                 // callback + sync versions
const fsp = require('fs/promises');       // promise version (works with async/await)

Almost every operation comes in three forms:

FormExampleBehaviour
Callbackfs.readFile(path, cb)Non-blocking, result comes in a callback
Synchronousfs.readFileSync(path)Blocks the program until it finishes
Promisefsp.readFile(path)Non-blocking, used with await

1. Reading a file

readFile loads the whole file into memory. If we don't pass an encoding like 'utf8', we get a Buffer (raw bytes) instead of text. 

fs.readFile('notes.txt', 'utf8', (err, text) => {
  if (err) {
    console.log('Could not read file:', err.message);
    return;
  }
  console.log(text);
});

For very large files (logs, videos) reading everything at once is a bad idea, so we read it in chunks using a stream: 

const stream = fs.createReadStream('big-log.txt', 'utf8');
stream.on('data', chunk => console.log('got', chunk.length, 'characters'));
stream.on('end', () => console.log('finished reading'));

2. Writing and appending

writeFile creates the file if it is not there, and replaces the old content if it is. appendFile adds to the end and keeps what was already there. 

// replaces the content
fs.writeFileSync('marks.txt', 'Name,Marks\n');

// adds new lines at the bottom
fs.appendFileSync('marks.txt', 'Arun,78\n');
fs.appendFileSync('marks.txt', 'Meena,91\n');

console.log(fs.readFileSync('marks.txt', 'utf8'));

Common mistake: using writeFile inside a loop to add rows. Each call wipes the file, so only the last row survives. Use appendFile for that.

Saving an object as JSON is also just a write:

const student = { name: 'Arun', dept: 'AI&DS', year: 2 };
fs.writeFileSync('student.json', JSON.stringify(student, null, 2));

3. Copy, rename and delete

fs.copyFileSync('marks.txt', 'marks-backup.txt');   // copy
fs.renameSync('marks-backup.txt', 'old-marks.txt'); // rename (also used to move)
fs.unlinkSync('old-marks.txt');                     // delete

rename can move a file into another folder by giving a new path, e.g. fs.renameSync('a.txt', 'archive/a.txt'). There is no "delete" function by that name, deleting a file is called unlink.

4. Working with folders

// make a folder (recursive: true also creates parent folders, no error if it exists)
fs.mkdirSync('uploads/2026', { recursive: true });

// list what is inside a folder
const items = fs.readdirSync('.');
console.log(items);

// remove a folder along with everything inside
fs.rmSync('uploads', { recursive: true, force: true });

5. Checking file details

fs.stat gives information about a file without opening it. fs.existsSync is a quick yes/no check. 

if (fs.existsSync('marks.txt')) {
  const info = fs.statSync('marks.txt');
  console.log('size      :', info.size, 'bytes');
  console.log('is file   :', info.isFile());
  console.log('is folder :', info.isDirectory());
  console.log('modified  :', info.mtime.toLocaleString());
}

6. Sync vs callback vs promise — which one to use?

The same task (read a file, count its lines) written all three ways:

// sync - simple, but the server can't do anything else while waiting
const data = fs.readFileSync('marks.txt', 'utf8');
console.log(data.split('\n').length);

// callback - older style, nesting gets messy with many steps
fs.readFile('marks.txt', 'utf8', (err, data) => {
  if (!err) console.log(data.split('\n').length);
});

// promise with async/await - reads top to bottom, errors go to try/catch
async function countLines() {
  try {
    const data = await fsp.readFile('marks.txt', 'utf8');
    console.log(data.split('\n').length);
  } catch (err) {
    console.log(err.message);
  }
}

Sync versions are fine for small scripts and for loading config once when the app starts. Inside a server that handles requests, the async versions should be used, otherwise one slow file read holds up every other user.

Part B — The url module

Introduction

When a request comes to a Node server, we only get the URL as one long string. The url module splits that string into its parts so we can find out which page was asked for and what values were sent in the query string. The main thing we use is the URL class. It is available globally, and the same class also exists in the browser. 

const link = new URL('https://shop.example.com:8080/books/search?title=node&page=2#reviews');

If the string is not a valid URL, new URL() throws a TypeError, so user input should be wrapped in try/catch. For a relative path like /about we must also give a base: new URL('/about', 'http://localhost:3000').

1. Parts of a URL

For the URL above, these are the properties we get:

PropertyValue
hrefthe full URL
protocolhttps:
hostshop.example.com:8080
hostnameshop.example.com
port8080
pathname/books/search
search?title=node&page=2
hash#reviews
originhttps://shop.example.com:8080

port is an empty string when the default port is used (80 for http, 443 for https). Also note host includes the port but hostname does not.

2. Query parameters (searchParams)

Everything after the ? is available as link.searchParams, which is a URLSearchParams object. Values always come back as strings. 

const q = new URL('https://site.com/products?cat=shoes&size=8&size=9').searchParams;

q.get('cat');        // 'shoes'
q.get('size');       // '8'  (only the first one)
q.getAll('size');    // ['8', '9']
q.has('color');      // false
q.get('color');      // null

for (const [key, value] of q) {
  console.log(key, '=', value);
}
MethodWhat it does
get(name)first value for that key, or null
getAll(name)all values as an array
has(name)true / false
set(name, value)sets the value, removes duplicates
append(name, value)adds another value, keeps existing
delete(name)removes the key
sort()sorts keys alphabetically
toString()gives back a=1&b=2 form

Since values are strings, q.get('page') + 1 gives '21', not 3. Convert with Number() first.

3. Changing and building URLs

The properties can also be assigned. This is safer than joining strings by hand because special characters (spaces, &, etc.) get encoded automatically. 

const api = new URL('https://api.example.com');
api.pathname = '/v1/movies';
api.searchParams.set('genre', 'sci-fi');
api.searchParams.set('q', 'star wars & more');
api.searchParams.append('year', '2024');

console.log(api.href);
// https://api.example.com/v1/movies?genre=sci-fi&q=star+wars+%26+more&year=2024

URLSearchParams can also be created on its own, which is handy for form data: 

const form = new URLSearchParams({ user: 'dev', city: 'Chennai' });
form.toString();   // 'user=dev&city=Chennai'

4. Other helper methods

const url = require('url');

// older API still seen in many tutorials - deprecated, prefer new URL()
const old = url.parse('http://localhost:3000/login?next=/home', true);
console.log(old.pathname, old.query.next);   // /login /home

// object back to a string
url.format({ protocol: 'http', hostname: 'localhost', port: 3000, pathname: '/about' });
// 'http://localhost:3000/about'

// convert between file paths and file:// URLs
url.pathToFileURL('/home/dev/report.pdf').href;       // 'file:///home/dev/report.pdf'
url.fileURLToPath('file:///home/dev/report.pdf');      // '/home/dev/report.pdf'

// check if a string is a valid URL without try/catch (Node 19.9+)
URL.canParse('not a url');   // false

Part C — Where these are actually used

Use case 1: Serving pages from a folder (mini static server)

The URL tells us which page the user wants; fs reads that file from a public folder and sends it back. If the file isn't there we send a 404. 

const http = require('http');
const fs = require('fs');
const path = require('path');

http.createServer((req, res) => {
  const { pathname } = new URL(req.url, 'http://localhost');
  const page = pathname === '/' ? 'index.html' : pathname.slice(1);

  // path.basename stops requests like /../../secret.txt from leaving the folder
  const filePath = path.join(__dirname, 'public', path.basename(page));

  fs.readFile(filePath, (err, content) => {
    if (err) {
      res.writeHead(404, { 'Content-Type': 'text/plain' });
      return res.end('Page not found');
    }
    res.writeHead(200, { 'Content-Type': 'text/html' });
    res.end(content);
  });
}).listen(3000);

Use case 2: Page visit counter saved in a file

Variables are lost when the server restarts, so the count is kept in a JSON file. Each request reads it, increases the count for that path, and writes it back. 

const COUNT_FILE = 'visits.json';

function countVisit(pathname) {
  let visits = {};
  if (fs.existsSync(COUNT_FILE)) {
    visits = JSON.parse(fs.readFileSync(COUNT_FILE, 'utf8'));
  }
  visits[pathname] = (visits[pathname] || 0) + 1;
  fs.writeFileSync(COUNT_FILE, JSON.stringify(visits, null, 2));
  return visits[pathname];
}

// inside the server
const { pathname } = new URL(req.url, 'http://localhost');
res.end(`This page has been visited ${countVisit(pathname)} times`);

Use case 3: Filtering data using the query string

A request like /students?dept=CSE&minCgpa=8 should return only matching students. The list is stored in students.json. 

http.createServer(async (req, res) => {
  const reqUrl = new URL(req.url, 'http://localhost');

  if (reqUrl.pathname === '/students') {
    const all = JSON.parse(await fsp.readFile('students.json', 'utf8'));
    const dept = reqUrl.searchParams.get('dept');
    const minCgpa = Number(reqUrl.searchParams.get('minCgpa') || 0);

    const result = all.filter(s =>
      (!dept || s.dept === dept) && s.cgpa >= minCgpa
    );

    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify(result));
  }
}).listen(3000);

Use case 4: Logging every request to a daily log file

Useful for seeing who visited what. A new log file is made each day, and appendFile keeps adding lines to it. 

function logRequest(req) {
  const u = new URL(req.url, `http://${req.headers.host}`);
  const today = new Date().toISOString().slice(0, 10);   // e.g. 2026-09-18
  const line = `${new Date().toLocaleTimeString()}  ${req.method}  ${u.pathname}  ${u.search}\n`;

  fs.mkdirSync('logs', { recursive: true });
  fs.appendFile(`logs/${today}.log`, line, err => {
    if (err) console.log('log failed:', err.message);
  });
}
